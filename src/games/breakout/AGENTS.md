# ブロック崩し

壊したブロックからボールが増え、最大 500 個まで膨らむブロック崩し。エンドレス（ブロックが降りてくる）とステージ（全部壊すとクリア）の 2 モードがある。画面は `src/app/breakout/` にある。

## 全体の組み立て

- `controller.ts`: 画面の状態機械。純粋関数で、画面のイベントから次の状態と、ゲームへの命令（`GamePort`）を決める。画面とゲームの間の型は `types.ts` にまとめてある
- `session.ts`: `GameSession`。画面を開いている間ずっと生きていて、レンダラー、描画のシーン、入力、フレームループ、BGM、明滅の制限を持つ。入力を受け付けるか、世界を進めるかは `session-state.ts` の純粋な状態から導く
- `run.ts`: `Run`。1 回のプレイで、`prepare` のたびに新しく作り、終わったら捨てる。sim、世界の時計、カメラ、演出の状態、効果音、演出ディレクターはすべてここに属する

プレイごとの状態は `Run` を作り直すことで初期化する。長く生きるオブジェクトに「初期値へ戻す」メソッドを足して使い回すと、戻し忘れた値が次のプレイへ持ち越されるため。長く生きるオブジェクト（`GameSession`、`BreakoutView`、`Bgm`）には資源（GPU のバッファ、音のノード、DOM のリスナー）だけを持たせる。

## 時間の軸

時刻を扱うときは、どの軸かを決めてから使う。1 フレームの時刻は `frame-time.ts` の `FrameTime` でまとめて渡す。

- `world`: プレイの世界時間。スローモーションで遅くなる。sim と、世界の中で起きる演出（ボールの回収、光の到着など）はこの軸
- `present`: シェーダーの `u.time` と同じ軸で、セッションの間は戻らない。粒や破片の発生時刻、衝撃波や壁の揺れの開始時刻はこの軸で渡す
- `real`: 実時間。明滅の制限、パドルの変形、ゲームオーバーから結果画面までの時間など、スローモーションの影響を受けないもの
- 音の時刻は `AudioContext` の時計（`audio.now()`）で予約する。ステージクリアの溜めは、無音と吸い込む音に合わせるため音の時計で測る

## sim（`sim/`）

- 決定的に動かす。乱数はシードつきの `Rng` だけを使い、`Math.random` や現在時刻を読まない。同じシードと入力なら同じ結果になる
- 120Hz の固定ステップで進める。入力は `step({ paddleTargetX, launch })` で 1 ステップずつ渡す。パドルの動きはセッションがフレーム内のステップへ均等に割り振るので、発射角は画面のリフレッシュレートで変わらない
- 調整値は `config.ts` の `tuning`。sim はプレイの開始時に `snapshotTuning()` で取った写しだけを読むので、書き換えは次のプレイから効く
- `determinism.test.ts` の既知の入力列の結果は、sim の規則を変えると変わる。変わった理由を確かめてから値を更新する
- sim のイベントは `Run` がフレームの初めに消し、そのフレームの全ステップ分を演出ディレクターが読む

## 演出（`fx/`）と描画（`view/`）

- Peak は、自己ベストを超えた瞬間の演出（`fx/peak.ts`。カメラの引きと揺れ、専用の和音、bloom の強調、振動）。ステージクリアのフィナーレ（`fx/finale.ts`）とは別の演出
- 演出ディレクター（`fx/director.ts`）は、sim のイベントをフレーム単位で集計してから、粒・音・カメラ・背景の演出にする。大量に起きる音は `SoundThrottle` で間引き、同じ種類の音は 1 フレームに 1 回にまとめる。音は、それを起こしたイベントがあったフレームでだけ鳴らす。先の時刻へ並べて予約したり、止んだ後に遅れて鳴らしたりすると、見た目とずれる
- 演出の状態 `FxState` は、ディレクターが毎フレームすべての値を書く。uniform に書き込むのは `BreakoutView.apply` だけにする。こうしておくと、新しい `Run` の最初のフレームで前のプレイの値がすべて上書きされる
- `fx/` は three.js に依存させない。`view/` から読むのは、three.js を使わない `look.ts`（明るさの調整値）と `palette.ts`（色）だけにする。演出は `FxState` の素の値として描画へ渡す
- 描画はフレームごとではなく、世界が進んだか、見た目が変わったときだけ行う。世界を進めずに見た目を変えたとき（設定、レイアウト、品質の変更など）は、セッションの `invalidate()` で描き直しを求める
- 明るさの調整値は `view/look.ts` に集める。シェーダーを速くするときは、変更前と同じ画素になることを確かめる（許す差は HDR で 1e-4 まで）

## 音（`sounds/`）

- 効果音（`BreakoutSfx`）はプレイごとに作り、そのプレイの `VoiceGroup` に属させる。プレイを捨てると、鳴り残りもまとめて止まる
- BGM（`Bgm`）は画面を開いている間ずっと使い回す。プレイの始めは `restart()`、一時停止は `pause()` / `resume()`
- 一度きりの大事な音（フィナーレ、ゲームオーバー、Peak の和音など）は優先度 `event` で鳴らし、頻繁な音に途中で切られないようにする

## ゲームの決まり（実装で迷いやすいもの）

- ステージクリアのボールボーナスは、クリアした瞬間に残っていたボールの数で決まる。クリア後、ボールは奈落に落ちない。演出を見ても飛ばしても最終スコアは同じになる
- 演出を飛ばせるのは、勝敗が決まった後に押したタップやキーだけ。決着の前から押していた指を離しても飛ばさない
- 勝敗が決まってから結果画面が出るまでは、一時停止できない（結果を確定させるため）
- 新記録は、スコアが前のベストを上回ったとき。HUD の NEW! と結果画面の NEW BEST! はいつでも出すが、新記録の演出（Peak）は前のベストが 0 より大きいときだけ出す
- ボール数は画面に出していないので、ボール数の段階が変わった瞬間に単発の演出は出さない。背景や BGM の変化は数秒かけて寄せていく
- 記録は `records.ts` が `localStorage` に保存する。保存形式を変えるときは、データの中の版（`v`）を上げ、前の版から移す処理を書く
- 壊れないブロック（`BlockType.Solid`、ステージの記号は `X`）はステージにだけ置く。ステージのクリアは、壊せるブロックの数（`breakableCount`）が 0 になったとき。`liveCount` は壊れないブロックも数える
- 壊せるブロックはどれも、壊れないブロックを通らずにボールが届く位置に置く（`parseStage` が確かめる）。壊れないブロックで横一列を塞ぐと、その上に入ったボールは左右の壁との隙間からしか下りられず、1 分以上戻ってこないことがある。列を塞ぐときは途中に通り道を空ける

## 見た目と画面の文言

- 長く遊んでも目が疲れない明るさに抑える。色の鮮やかさは保ち、明るさだけを控えめにする
- 振動は、ボールが 0 個になったとき、Peak、ステージクリアのフィナーレだけで使う
- 画面の文言は、事実を短く平易に書く。モードの説明などは「〜です。」の文にする。キャッチコピー調の言い回しは使わない

## テストと確認の道具

- `sim/sim.test-support.ts`: 盤面を組んだ sim を作る補助
- `fx/test-kit.test-support.ts`: 本物の sim と時計で演出ディレクターを動かし、呼ばれた音や演出を記録する環境
- `src/juice/audio/mock-audio.test-support.ts`: 作られたノードと AudioParam の変化を記録する、偽の AudioContext
- 開発ビルドでは、画面左下の調整パネルと、開発者ツールの `window.__breakout`（`setDebugAutoplay(true)` で自動操作、`debugAddBalls(n)` でボールを追加）が使える
- 開発ビルドでは、URL に `?backend=webgl` を付けると WebGL2 で描画する
