# リバーシ

世界オセロ連盟の規則どおりの 8×8 のリバーシを CPU と対局し、スコアを競う。人は黒（先手）か白（後手）を選ぶ。規則は変えず、石を置く・返す・数えるたびの演出を振り切る。コンボ（素早く打ち続ける）と、返した枚数・角・確定石・終局の石の数・勝敗から得点を積む。画面は `src/app/reversi/` にある。

## 全体の組み立て

- `controller.ts`: 画面の状態機械（タイトル → 対局中 ⇄ 一時停止 → 終局の儀式 → 結果）。純粋関数で、記録は `records-model.ts` の型と窓口（`RecordsStore`）だけを知る。ゲームが対局を始めたと知らせたら（`started`）、どの画面からでもその設定の対局中へ移る（開発用の操作口から始めた対局も画面が追う）。画面とゲームの間の型は `types.ts` にまとめてある
- `session.ts`: `GameSession`。対局を始めるたびに、その設定を `started`（`SessionEvent`）で画面へ知らせる。画面を開いている間ずっと生きていて、描画一式とフレームループ（`RenderDriver`）、描画のシーン、入力（`PointerInput`）、BGM、明滅の制限を持つ。入力を受け付けるか、世界を進めるかは `session-state.ts` の純粋な状態から導く。盤の上の文字（`Callout`）の位置を、ワールド座標から描画領域の CSS ピクセルへ直して画面へ渡す
- `run.ts`: `Run`。1 回の対局で、始めるたびに新しく作り、終わったら捨てる。対局の進行（`match.ts`）、コンボ（`combo.ts`）、得点（`scoring.ts`）、確定石の追跡（`stable-tracker.ts`）、世界の時計、カメラ、演出の状態、効果音、演出ディレクターを持ち、段階（始まりの演出 → 人の手番・CPU の手番 → 着手の演出 → パス → 終局の儀式）を進める。終局した段階で結果（`RunResult`）を 1 回だけ作り、儀式と確定の知らせが同じものを使う
- `match.ts`: 1 局の進行（手番、着手、パス、終局と判定）。時刻・演出・得点は知らない
- `stable-tracker.ts`: 手ごとに、打った後の局面から新しく確定石になったマスを色ごとに返す。どちらの手でも渡す
- `geometry.ts`: マスのワールド座標と、画面への盤の配置（CSS ピクセルとマスの変換）
- `hud/`: HUD の表示。`model.ts` が石の数の跳ね・綱引きのバー・転がって増える得点を決め、`writer.ts` が前のフレームから変わった値だけを書き込み先（`dom.ts`）へ渡す。`layout.ts` は、測った矩形から盤を収める上下の余白を求める
- `settings.ts`: リバーシの設定（画面の揺れ・効果音・BGM）。`juice/settings.ts` の `standardSettingsSchema` で作る
- `config.ts`: 動きと時間の調整値（着手の時間割、段階、ヒットストップ、スローモーション、カメラの動き、振動、波紋と衝撃波、画面の空気、終局の儀式）。明るさの調整値は `view/look.ts`

## ルール（`rules/`）

- マス s は `行 × 8 + 列`（a1 が 0 で左上、行は上から 1〜8）。64 マスは 32 ビット整数 2 つ（`lo` が 1〜4 行、`hi` が 5〜8 行）のビットボードで持つ
- 初期配置は d4・e5 が白、e4・d5 が黒で、黒から打つ。打てる手がないときだけパスし、どちらも打てなくなったら終局
- 勝敗は石の数で決める（`resultOf`）。同じ数なら引き分け
- 確定石（`stableDiscs`）は、4 本の線のそれぞれで「線に空きマスがない」か「片側が盤の外か同じ色の確定石」の石を広げていく。漏れはあるが、返りうる石を確定石と判定することはない。そのため、一度確定石になった石は同じ色のまま確定石であり続ける
- `rules/` は素のモジュール。合法手と返る石は、1 マスずつ歩く素朴な実装（`reference.test-support.ts`。テスト用の `legalSquares` と `isOver` もここ）とランダムな対局の全局面で突き合わせて確かめる

## CPU（`ai/`）

- 強さは 1 つだけ。スコアを競うゲームなので、まともに打てば勝てる強さに留める（2 手先まで読む打ち手なら必ず勝てることを `cpu.test.ts` で確かめる）
- `cpu.ts` の `chooseMove` は、1 手先の局面を `evaluate.ts` で評価し、揺らぎを足していちばん高い手を選ぶ。ときどき読まずに打つ。素のモジュールで、同じ局面と乱数の列なら必ず同じ手を返す
- 手は手番が来たときにその場で選び、最短の思考時間（`config.ts` の `MIN_THINK`、実時間）を待ってから打つ。コンボのテンポを切らないよう短くしてある

## コンボと得点

- コンボ（`combo.ts`）: 人の手番が始まってから `COMBO_WINDOW` 秒（世界時間）以内に打つと 1 つ積み、間に合わなければ途切れる。途切れた後に打った手は新しいコンボの 1 手目（1）になり、続けて間に合えば 2、3 と積む。窓は人の手番が始まったとき（CPU の石が返りきったとき）に開ける。人がパスしたら途切れる。CPU がパスしても途切れず、パスの表示を待たずに人の手番を始める。終局したら窓を閉じてコンボを 0 にし（最大は残す）、フィーバーを止める
- コンボの数は HUD に固定では出さない。2 以上に積まれた手だけ、石が着いた瞬間に置いた石の位置へ数を出す。HUD には、得点の段の右に窓の残りのゲージだけを出す
- コンボが `FEVER.start` 以上でフィーバーになり（強さは `feverLevel`）、光をビートに乗せ、BGM の段階を上げ、ヒットストップを長くする
- 早打ち: 人の手番が始まってから `QUICK_WINDOW` 秒（世界時間。コンボの窓よりかなり短い）以内に打った手は、コンボとは別に早打ちの点（`SCORE.quick`）を足す。対局の最初の手番は除く。倍率は掛けない。盤の上の得点の文字に QUICK を添え、結果画面では回数と点を別の行で出す
- フルコンボ: 盤が全部埋まって終局するまで、一度も途切れなかった（窓を過ぎた、窓の外で打った、人がパスした、のどれもない）とき、終局で最大コンボの点の代わりに `SCORE.fullCombo` を付ける。結果画面では最大コンボの最上位として、最大コンボの行の代わりに FULL COMBO の行で出す
- 得点（`scoring.ts`）: 人の 1 手ごとに、返した石（n 枚目が n × 10 点）・角・その手で新しく確定石になった人の石の点にコンボの倍率（1/10 単位で持つ）を掛け、早打ちなら早打ちの点を足す。CPU の手で確定石になった人の石は、どの手の点にも数えない。終局で、石の数・勝ち・パーフェクト・コンボ（最大コンボか、フルコンボ）の点を足す。多く返すことだけを狙って負けるより、勝つほうが高い点になるように配点する
- 結果（`RunResult`）の石の数・最大コンボ・フルコンボか・早打ちの回数は結果そのものが持ち、得点の内訳（`ScoreSheet`）は点だけを持つ。`newBest` は、合計がこれまでの最高スコア（0 より大きいとき）を超えたか
- HUD の得点（`HudState.score`）は画面に出す得点で、人の手の点は得点の文字を出したとき（石が返りきった後）に、終局の石の点は儀式で数えたときに足す。`HudState.newBest` は、対局中の得点が最高スコアを超えた（その演出を出した）かで、終局の石の点では変わらない

## 時間の軸

時刻を扱うときは、どの軸かを決めてから使う。1 フレームの時刻は `src/juice/frame-time.ts` の `FrameTime` でまとめて渡す。

- `world`: 対局の世界時間。スローモーションで遅くなり、ヒットストップで止まる。対局の段階の進行、演出の予定（`CueQueue`）、コンボの窓はこの軸
- `present`: シェーダーの `u.time` と同じ軸で、セッションの間は戻らない。石の動き（`DiscField`）、粒、波紋、衝撃波の時刻はこの軸で渡す（present = そのプレイの presentOffset + world）
- `real`: 実時間（シェーダーの `u.real`）。対局は、始めたときのセッションの実時間から続ける。CPU の最短の思考時間、滑らかな変化、明滅の制限、ヒットストップの間も動くもの（背景、盤の照り返し、止めた石の震え、集中線）
- 着手の時間割（`fx/choreo.ts` の `MoveChoreo`）の時刻は、手の始まりからの相対時刻。予定に並べるときは、手の始まりの世界時間を足した絶対時刻にする
- `WorldClock.slowMo` の保つ長さは実時間なので、世界の中で起きることの長さ（世界時間）だけ遅くするときは、`WorldClock.slowMoWorld` に世界時間の長さを渡す

## 演出（`fx/`）と描画（`view/`）

- 1 手の演出は、`choreo.ts` が着手から時間割を決め、`director.ts` が予定（`cue-queue.ts` の `CueQueue`。時刻の順に並べ、先頭から取り出す）に並べて、時刻の来たフレームで石の見た目・音・粒・カメラ・文字を出す。音は、それを起こした出来事（石が着く、返りきる）のフレームで鳴らす
- `Director` は部品を束ねる: 画面全体の空気（`atmosphere.ts`）、盤の波紋と衝撃波（`board-waves.ts`）、押しているマスとカーソル（`pointer-fx.ts`）、HUD の得点と最高スコアの更新（`score-ticker.ts`）、粒（`particle-fx.ts`）、終局の儀式（`ceremony.ts`）。儀式は必要な口（`CeremonyAir` など）だけを受け取る
- 演出の状態（`FxState`）は、値のまとまりごとに書く部品を 1 つに決める（`fx-state.ts` に書いてある）。描画（`view/scene.ts` の `ReversiView.apply`）は毎フレームすべての値を uniform に写す
- 返る向き（`FlipCue` の `dirX`・`dirY`、押している間の予告の `previewFlips`）は、`choreo.ts` がワールド座標（盤の右と上が正）で出す
- 石ごとの見た目の状態は `discs.ts` の `DiscField`（three.js を知らない）。落ちて着くまでの長さも石ごとに書く。描画（`view/discs.ts`）は版が変わったときだけ GPU へ写し、動きはシェーダーが時刻から計算する。盤に見える色（`shown`）は石が返りきったときに変わり、HUD の石の数はこれを数える
- `DiscField` と演出の状態の「まだ起きていない」は、時刻 `LONG_AGO` で表す。シェーダーで「その時刻から後」を判定するときは、`LONG_AGO` の値を起きていないものとして除く。波紋と衝撃波は、描く長さ（`RIPPLE.life`・`SHOCKWAVE.life`）の外として除く
- 波紋（`RIPPLE`）は盤の線（`view/board.ts`）と石の跳ね（`view/discs.ts`）が同じ値で描く。衝撃波（`SHOCKWAVE`）は枠を順に使い、重なっても前の輪を消さない
- シェーダーの決まりはルートの `AGENTS.md` に従う。頂点の式で波紋や衝撃波の枠を扱うときは、`Loop` を使わず、枠の数だけ式を足し合わせる
- 演出の段階は、人の手で返した枚数から決める（`config.ts` の `FLIP_TIERS`: 3・5・6・8 枚）。閾値は、この CPU との対局で実際に出る枚数の分布から決めてある
- 段階 1 以上の人の手は、石が着いた瞬間にヒットストップする。世界の時間を止め（`WorldClock.hitStop`）、打った石と返る石を実時間で横に震わせ（60fps で見分けられる 12 Hz）、閃光・集中線（`view/impact.ts`）・RGB のずれ（`PostChain` の aberration）・カメラの突きを重ねる。長さは `hitStopFor`（段階とフィーバーから、上限つき）
- 段階 3 以上（`BIG_TIER`）は、着いた音の立ち上がりを聞かせてから、ヒットストップと返り始めるまでの溜めの間を無音にし（`AudioEngine.silence` の delay。対局を捨てるときは解く）、スローモーションと衝撃波で返す
- 画面全体の明滅と bloom のブーストは `Atmosphere.flare` だけが出す。1 回の光（着いた瞬間、返り始め、最高スコアの更新）ごとに、フラッシュとブーストをまとめて `FlashLimiter` の許可を 1 回だけ求める
- 1 手の時間割は短くし、打ってから次の手番までのテンポを保つ（`config.ts` の `CHOREO`）。ヒットストップの長さは時間割とは別に決める
- 人の手は、落ちる間の風を切る音・着いた瞬間の打撃とコンボの音・返りきるたびの枚数の数え上げ・返りきった後の得点の文字と音を出す。最高スコアの更新は、得点の後に少しずらして出す。次の手番はこれらの知らせを待たない（終局する手だけは、出しきってから終局の儀式に入る）
- 文言は事実（枚数、得点、倍率、コンボの数、CORNER、COMBO、PASS）だけにする
- CPU の手は人にとっての損なので、祝福に見える演出を付けない。ヒットストップもしない。重く落ち、下がっていく音と、下へ落ちる暗い粒にし、多く返したら盤と背景を暗くする。文字は出さない
- カメラをビートで動かさない。光をビートに乗せるのはフィーバーの間だけ（合法手の印の脈打ちも同じ）
- 終局の儀式（`ceremony.ts`）: 全部の石が一度に跳ねてから、1 組（人の石と CPU の石 1 つずつ）ずつだんだん速く、元の位置で白く光りながら縮んで消え（消える音）、消えたまま少し間を置いて（移っている間）、色ごとに並べ直す位置に大きく現れる（人の石は左上から、CPU の石は右下から）。移動と数え上げは同時に進め、現れた瞬間にその組を数えて盤の上側の集計（人と CPU の数を並べ、多い側を大きく明るく見せる）を増やし、人の石なら HUD の得点に石の点を入れる。多い側だけが最後まで続ける。数え終えた集計を少し見せてから（`CEREMONY.countHold`）無音で溜め、集計の下に決着を叩きつけ、勝ちは人の石の波で締める。集計と決着は、結果画面に移るまで並べて出しておく。終局のボーナス（勝ち・パーフェクト・コンボ）は儀式では出さず、結果画面の内訳で見せる。儀式を終えると（飛ばしても）、HUD の得点は対局中の得点に石の点を足した値になる
- 儀式でも、勝ちだけが上がっていく音（跳ねる音・人の石を数える音・溜めの吸い込む音）・衝撃波・花火・着地と数えた石の粒・光・演出の強さの上乗せ・明るい和音。負けと引き分けの音は上がらない版（`rising` が false）で鳴らし、負けは石を暗くして低い和音にする。タップで飛ばせ、飛ばすと溜めの無音と吸い込む音を止める。飛ばしても結果は変わらない
- 最高スコアの更新は、対局中の得点が最高スコアを超えた瞬間。記録があるとき（0 より大きいとき）に 1 局に 1 回
- 盤の線の色は手番を表す（人はミント、CPU はマゼンタ）。背景のように色相を回さない。虹色にするのは段階 4 の手、最高スコアの更新、勝ちの締めの波、パーフェクトだけ
- 止めた石の震えと RGB のずれは、設定の「画面の揺れ」と「視差効果を減らす」から決まる倍率（`CameraMotion.jolt`）を掛けて弱める
- 明るさの調整値は `view/look.ts`（演出ごとの光と暗さは `LOOK.moments`）、色は `view/palette.ts` に集める。動きと時間の調整値は `config.ts`

## 音（`sounds/`）

- 効果音（`ReversiSfx`）は対局ごとに作り、その対局の `VoiceGroup` に属させる。物量で押せないので、1 発ごとに層（破裂音・硬い打撃・歪ませた胴鳴り・下がる重低音・残響）を重ね、段階が上がるほど金属の打撃と爆発の尾を足す。残響・歪み・ノイズはエンジンの共通の部品（`synth.ts` の `send`・`drive`・`noise`）を使う
- 数が増え続ける音程（返る石、コンボ、数え上げ、始まりの石）は Shepard tone にし、何枚目でも可聴域に収める（`sfx.test.ts`）
- 溜めの吸い込む音（`inhale`）は `synth.ts` の `riserInhale` を lead の経路で鳴らし、止める口（`SoundHandle`）を返す。止めると voice ごとフェードアウトする（`Voice.stop`）
- BGM は、`sounds/bgm.ts` の曲の中身（`REVERSI_ARRANGEMENT`）を `LayeredBgm` で鳴らす。盤に置かれた石が増えるほど、またフィーバーの間は層を足し、空きマスが 14 以下になると終盤の高まりを上げる

## 記録

- 記録の値と検証・合成・更新は `records-model.ts`（素のモジュール）、`localStorage` への保存は `records.ts`（対局数、勝ち・負け・引き分け、パーフェクト、最高スコア、最大コンボ）。保存形式を変えるときは版（`v`）を上げる。前の版の保存内容は捨てる
- 別のタブの記録と合わせるときは、項目ごとに大きいほうを取り、対局数を勝ち・負け・引き分けの合計以上に、パーフェクトを勝ちの数以下にそろえる
- 開発用の操作口から任意の局面で始めた対局は練習（`RunResult.practice`）で、結果画面には出すが記録しない
- 最後に選んだ色は、記録とは別に覚える（`reversiPrefs`）

## テストと確認の道具

- `fx/test-kit.test-support.ts`: 本物の対局・時計・確定石の追跡で演出ディレクターを動かし、呼ばれた音・無音・光の許可・演出を世界時間つきで記録する環境
- `session.test.ts`: 描画・入力・時計を代役にして、打つ・CPU が打ち返す・コンボと得点・パス・キーボード・終局まで通す・儀式を飛ばす・GPU の作り直しを確かめる
- `view/scene.test.ts`: 演出の状態のすべての値から uniform への写し方、どのシェーダーも写した uniform（波紋・衝撃波の枠を含む）を読むこと、`smoothstep` の両端の順。シェーダーの式は `src/engine/node-graph.test-support.ts` で辿る
- `fx/pointer-fx.test.ts`: 押しているマスの予告と光、キーボードのカーソル
- `sounds/bgm.test.ts`: 石の数から決まる BGM の段階と、段階ごとに鳴らす層とリズム
- 開発ビルドでは、画面左下のパネルと、開発者ツールの `window.__reversi` が使える。`setDebugAutoplay(true)` で人の手番が来たら CPU と同じ選び方ですぐ打ち（コンボが積み上がる）、`debugStart(rows, turn, human)` で任意の局面から練習の対局を始め（8 行の各 8 文字、X が黒、O が白、. が空き）、`debugPlay('a1')` で人の手を打つ。大きな手の演出はこれで確かめる
- 開発ビルドでは、URL に `?backend=webgl` を付けると WebGL2 で描画する

## 画面の文言

- 画面の文言は、事実を短く平易に書く。説明は「〜です。」の文にする。キャッチコピー調の言い回しは使わない
